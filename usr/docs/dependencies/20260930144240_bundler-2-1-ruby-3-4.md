# Legacy test dependencies fail on Ruby 3.4

## Dependency

Bundler was locked to 2.1.4, Rake to 10.5.0, and RSpec to 3.8.0 in `Gemfile.lock`. Honeybadger 4.7.2 loads `bigdecimal` without declaring it. The test workflow now runs Ruby 3.4.

## Symptom

Bundler 2.1.4 exits before dependency resolution with `uninitialized constant DidYouMean::SPELL_CHECKERS`. After Bundler starts, Rake 10.5.0 fails with `undefined method '=~' for Proc`. Loading the application fails with `cannot load such file -- bigdecimal`.

## Evidence

Run `bundle install` with Ruby 3.4.7 and Bundler 2.6.9 while `Gemfile.lock` declares Bundler 2.1.4. Bundler installs and restarts under 2.1.4, then fails in its vendored Thor error handling when it references `DidYouMean::SPELL_CHECKERS`.

After changing the lockfile to Bundler 2.6.9, run `bundle exec rake`. Rake 10.5.0 fails before executing tasks. Run `bundle exec rspec`; Honeybadger loads from `lib/kisko/doorbell/cli.rb`, warns that `bigdecimal` is no longer a default gem, then raises `LoadError`.

## Suggested fix

Generate the lockfile with Bundler 2.6.9, use current Rake 13 and RSpec 3.13 releases, and declare `bigdecimal` as a runtime dependency while Honeybadger 4 remains in the graph. Let `ruby/setup-ruby` install the locked Bundler version in CI.

## Next

Keep the lockfile Bundler version aligned with the supported Ruby version when the CI toolchain changes.

## Source

`Gemfile.lock` and `.github/workflows/test.yml`.

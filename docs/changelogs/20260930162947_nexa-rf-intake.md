# Nexa RF intake

## Decisions

Replace the Honeywell 868.3 MHz receiver contract with Nexa protocol 96 at 433.92 MHz. Keep the receiver at 250000 samples per second and enable only protocol 96 because protocol 51 decodes the same transmission again as Proove.

Require both the configured transmitter identifier and the `ON` state before delivering a Slack notification. Keep model, channel, unit, and group as diagnostic fields rather than identity inputs.

Bundle the smallest successful captured signal as the test-mode fixture.

## Effects

The receiver command now selects protocol 96, 433920000 Hz, and 250000 samples per second. Test mode replays `signals/g006_433.92M_250k.cu8`.

The message job rejects `OFF` events and events from other transmitters. Focused specs cover the live command, replay fixture, accepted press, non-press state, and foreign identifier.

RFC 0100 records the proposed intake contract and its capture evidence. RFC 0101 separates thermal operation from RF identification.

## Next

Release the changes with a new gem version. Install the artifact on the doorbell host, configure the Nexa transmitter identifier, and validate live presses before advancing RFC 0100 to Stable.

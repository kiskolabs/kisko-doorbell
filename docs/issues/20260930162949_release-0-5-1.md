# Release 0.5.1

## Decisions

Use 0.5.1 as the next version because the Nexa implementation changes gem contents after the existing 0.5.0 tag. Build only after all intended files are committed because the gemspec reads its package list from `git ls-files`.

Validate the built artifact on the doorbell host before tagging or publishing. Public gem publication remains a separate explicit action because the gemspec does not yet name an actual push host.

Keep runtime credentials out of process arguments. The previously exposed Slack credential must be rotated before deployment, and the service needs a non-argument credential input before the release is production-ready.

## Effects

The release process is recorded in `.agents/project.md` and appears in the Pray-managed project context after regeneration. `CHANGELOG.md` now collects the pending user-visible changes under `Unreleased`.

No version bump, tag, remote push, gem publication, or host deployment has been performed by this documentation change.

- Tag and publish only after successful live validation and explicit authorization.

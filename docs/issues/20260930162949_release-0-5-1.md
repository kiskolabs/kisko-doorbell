# Release 0.5.1

## Decisions

Use 0.5.1 as the next version because the Nexa implementation changes gem contents after the existing 0.5.0 tag. Build only after all intended files are committed because the gemspec reads its package list from `git ls-files`.

Validate the built artifact on the doorbell host before tagging or publishing. Public gem publication remains a separate explicit action because the gemspec does not yet name an actual push host.

Keep runtime credentials out of process arguments. The previously exposed Slack credential must be rotated before deployment, and the service needs a non-argument credential input before the release is production-ready.

## Effects

The release process is recorded in `.agents/project.md` and appears in the Pray-managed project context after regeneration. `README.md` provides the manual workstation and Raspberry Pi commands. `CHANGELOG.md` records the prepared 0.5.1 user-visible changes with the release date.

The executable accepts a restricted Slack token file, and startup failures report unreadable paths without logging token content. RFC 0102 records the new command-line contract. The source version and changelog are prepared for 0.5.1.

The source test and lint gate passes with ten examples and no offenses. A pre-commit package build reports version 0.5.1 and contains the executable, Nexa fixture, changelog, and changed runtime files. The final package must be rebuilt after committing RFC 0102 because the gemspec includes only paths known to `git ls-files`.

The Raspberry Pi installation command allows remote dependency resolution. `gem install --local` rejected the release when the host did not already contain `bigdecimal ~> 3.1`; installing the local gem path without `--local` lets RubyGems retrieve missing runtime dependencies.

No tag, gem publication, or host deployment has been performed.

## Next

- Commit the complete release source, rebuild the gem, and confirm RFC 0102 and the Nexa fixture are packaged.
- Install and validate the artifact on the doorbell host.
- Tag and publish only after successful live validation and explicit authorization.
